# Block-Centric Feature Implementation Plans

Generated by the improve skill on 2026-07-22 and refreshed after fast-forwarding Reflect to upstream commit `cedba83c`.

These plans add block-aware behavior without replacing Reflect's note/file model. Markdown remains durable; SQLite remains a rebuildable projection; a note remains the save/sync/privacy unit. Execute in order unless the dependency notes say otherwise. Every executor must read its plan fully, honor STOP conditions, run all verification gates, and update the status row.

## Target product shape

The planned first-wave contract is:

```markdown
- An addressable bullet about the storage decision ^k7m2q9ab
```

```markdown
[[Architecture#^k7m2q9ab|An addressable bullet about the storage decision]]
![[Architecture#^k7m2q9ab]]
```

The first form renders as a human label; the second renders as native-looking source content. The durable `^k7m2q9ab` exists in Markdown but is not normal UI.

Terminology:

- **Block reference**: an address/link to a particular list item.
- **Block embed/transclusion**: render the referenced source block inline.
- **Occlusion**: hiding content for recall; not part of these plans.

First wave supports list items (ordinary/ordered/collapsed bullets, square checkboxes, and Reflect round tasks). It does not make every paragraph or heading a durable block object.

## UX contract

The UX combines the best ideas from modern PKMs without adopting their block-database storage models:

- **Obsidian underneath**: portable, on-demand `^id`, `[[Note#^id|label]]`, and `![[Note#^id]]` Markdown.
- **Tana during creation**: keyboard-first block search showing content, source note, and disambiguating breadcrumbs.
- **Workflowy/Dotflowy when rendered**: transcluded content looks like ordinary content, with low-noise mirror chrome and an “Appears in N places” affordance.
- **RemNote conceptually**: references point; portals/transclusions window content. Keep those intents visibly and verbally distinct.
- **Notion only on interaction**: a subtle focus/hover boundary and provenance controls, not an always-on colored card.

Non-negotiable presentation rules:

1. A source block's trailing `^id` is hidden in normal live preview, including when the caret is in that block. It is visible only in an explicit raw-Markdown/source-editing surface.
2. A rendered block reference never exposes `Note#^id`; picker/copy actions author a sanitized human alias from the block's text.
3. A transclusion uses the editor's native typography, list marker, indentation, and spacing. It is not a prominent card and does not show an always-on source header.
4. A small mirror glyph/count may remain visible; provenance, source jump, and boundary appear on hover, focus, or keyboard activation.
5. “Appears in N places” lists the source and other transclusion locations with breadcrumbs and jumps to each location. Raw IDs never appear.
6. Missing, ambiguous, cyclic, or stale content remains legible and non-destructive without technical identifiers.
7. The first wave is read-only. Editing through a mirror remains a separate concurrency/session project.

## Dependency graph

```text
001 Markdown/parser contract
 ├── 002 Meowdown identity + reveal ──┐
 └── 003 index + resolution ─────────┼── 004 navigation/copy/backlinks
                                     │      └── 005 block picker/reference authoring
                                     │              └── 006 read-only transclusion
                                     └────────────────────────────────────────────
```

- **001 is the public-format gate.** Do not implement downstream syntax until maintainers approve `docs/block-addressing.md` and its exact-first compatibility rules.
- **002 is a separate first-party repository change.** Production editor support must land and release from `prosekit/meowdown`; do not patch/fork it in Reflect.
- **002 and 003 can run in parallel after 001.** They meet at 004.
- **005 follows 004** and adds the source-side discovery/insertion workflow. **006 follows 005** so embed authoring reuses the same picker, stale guards, and on-demand ID minting.
- Each schema plan appends the next migration number available at execution time. If another migration lands first, renumber the new migration and update `LATEST_SCHEMA_VERSION`; never edit shipped SQL.

## Milestone gates

### Gate A — after Plan 001

Maintainers approve:

- Obsidian-compatible `^id` / `#^id` syntax;
- list-item-only first-wave scope;
- on-demand ID minting;
- exact full note target before fragment fallback;
- duplicate IDs are ambiguous, never auto-repaired.

If any item is rejected, revise Plan 001 and re-vet all later plans before implementation.

### Gate B — during Plan 002

Meowdown proves through tests that IDs survive edit/drag/undo, drop on copy/paste, split deterministically, and serialize without loss. If not, stop the initiative rather than creating unstable references.

### Gate C — during Plan 006

Meowdown proves a standalone block embed can render and insert nested block content with valid DOM, exact source serialization, and sane caret/clipboard behavior. Before full wiring, maintainers also approve a small visual specimen covering idle, hover/focus, collapsed, loading, and missing states: native content rhythm, no card, no visible ID, and discoverable provenance. If either structural or visual gate fails, ship references without transclusion.

## Keeping the fork close to upstream

Current topology at planning time:

- `origin` → `jasonlong/reflect-open` (the fork)
- `upstream` → `team-reflect/reflect-open`
- local `master` tracks `upstream/master` and was fast-forwarded to `cedba83c`
- `origin/master` is 27 commits behind `upstream/master` after that fetch (`0` fork-only / `27` upstream-only); fast-forward it before publishing feature branches

Treat upstream compatibility as an architectural requirement:

1. **Keep `master` pristine.** Never commit feature work directly to it. Before starting the sequence, with no tracked changes:

   ```bash
   git fetch upstream
   git switch master
   git merge --ff-only upstream/master
   git push origin master
   git switch -c block-ref
   ```

2. **Use one linear implementation branch and one completion commit per numbered plan.** Do not mix work from the next plan into the current plan's commit. Rebase on `upstream/master` only at clean plan boundaries, never mid-plan; re-run the next plan's drift check after a rebase.
3. **Push only to the fork.** Push `master` and topic branches only to `origin` (`jasonlong/reflect-open`). Never run `git push upstream`, never create a branch/ref in `team-reflect/reflect-open`, and never use the upstream remote as a PR head. Open fork-local PRs against `jasonlong/reflect-open:master`. Creating a cross-repository upstream PR requires a separate explicit user instruction.
4. **Keep one reviewable concern per plan commit.** Avoid broad renames, formatting sweeps, compatibility shims, duplicated resolver paths, or unrelated refactors that enlarge future conflicts. Push checkpoints only to `origin`; use one fork-local PR for the completed linear stack unless the user requests otherwise.
5. **Make editor capabilities generic in Meowdown.** Develop Meowdown changes on a contributor fork and never push branches directly to `prosekit/meowdown`. Reflect should consume public released APIs; no patch-package, vendored editor, private package build, or undocumented ProseKit hook. Because a release may require an upstream PR, pause for explicit user approval before opening one.
6. **Keep Reflect additions additive and isolated.** New parser/query helpers, components, hooks, and providers live in focused files; existing hotspots receive only narrow delegation/composition changes.
7. **Rebase before creating a migration.** Use the next migration number after current upstream, regenerate DB types, and never modify an upstream migration. If numbering collides, renumber the unmerged migration during rebase.
8. **Keep generated/release churn minimal.** Commit generated Kysely output only when schema changes require it; never edit versions, changelogs, release-please manifests, or generated Tauri projects manually.
9. **If Reflect upstream does not take the feature**, keep the work as a small linear topic stack in `origin`, rebased onto `upstream/master`; do not turn fork `master` into a merge-history integration branch. Generic Meowdown submission/release remains a separate user-approved decision.
10. **Before each PR and after each upstream sync**, run the plan's targeted tests plus `pnpm check`; plans touching the desktop Rust crate also stage sidecars and run targeted Cargo tests.

A conflict in editor architecture, route shape, schema migration numbering, or note-session ownership is a drift signal—not permission to add a parallel fork-only implementation.

## Cross-plan invariants

All plans must preserve these rules:

1. Markdown files are the durable content source; block/index rows are rebuildable.
2. `private: true` content never reaches external services through reference/embed expansion.
3. Note sessions remain the write owner; no command writes behind an open editor.
4. IDs are generated only by explicit address/copy actions, including selecting a result in the block picker.
5. Duplicate IDs never resolve by row order.
6. Missing targets remain visible/unresolved; no silent content transfer.
7. Existing note names containing `#` continue resolving exactly before fragment fallback.
8. Block ID markers stay out of normal live preview, reference labels, transclusions, plain text, task labels, breadcrumbs, FTS, embeddings, and rendered snippets.
9. Human reference labels are sanitized snapshots of block text; IDs remain only in the hidden target address and explicit raw source.
10. Read-only transclusion never creates a second editable copy or implicitly expands into AI/export/publishing.
11. Keyboard and mobile navigation remain usable; reveal must not raise the mobile keyboard unexpectedly.
12. Fork-only code does not duplicate or replace upstream editor, resolver, session, or routing machinery.

## Findings considered and rejected

- **Replace Markdown notes with a Roam-style block database** — rejected. It conflicts with one-note-per-file portability, note-session saves, file sync, and rebuildable SQLite. Addressable projections provide most of the requested value without changing the source of truth.
- **Assign an ID to every block automatically** — rejected. It creates noisy Markdown, unnecessary writes/sync conflicts, and app-authored mutations after external edits. IDs are on-demand.
- **Use opaque `((global-block-id))` as the primary syntax** — rejected for the first wave. `[[Note#^id]]`/`![[Note#^id]]` is readable, note-scoped, and interoperable with Obsidian-style Markdown.
- **Store IDs in hidden SQLite only** — rejected. Rebuilds, another device, and external tools would lose the address.
- **Use HTML comments as the primary block-ID syntax** — rejected for the first wave. Comments are portable but custom and less interoperable; the chosen suffix has an existing note-tool convention. Revisit only if Meowdown cannot preserve suffix semantics.
- **Block-level tags and tag-occurrence UI** — omitted from this sequence by product decision. Existing note-level tags remain unchanged; block work focuses on references, contextual backlinks, discovery, and transclusion.
- **Edit source blocks directly through embeds** — deferred/rejected for this sequence. It introduces multi-document session, dirty-buffer, conflict, undo, and sync semantics. Plan 006 is read-only.
- **Add block-level history, cross-note block moves, or block-level privacy** — deferred. A note remains the save/sync/privacy unit.
- **Render transcluded content into FTS, embeddings, AI context, gist publishing, or export** — rejected by default. It duplicates content and creates privacy/provenance ambiguity; authored embed syntax remains the durable/indexed content.
- **Always-on technical IDs or Roam-style ID labels** — rejected. IDs are a storage concern; normal references use human aliases and transclusions use subtle mirror chrome.
- **Large card-style transclusions with persistent source headers** — rejected. They compete with the editor. Use native content styling and reveal provenance on interaction.
- **Per-block floating backlink badges in the editor gutter** — deferred. The existing bottom backlinks panel can expose target-block context first with much lower editor/render cost; Plan 006 may add a bounded mirror-place count only for rendered transclusions.
